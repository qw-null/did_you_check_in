# 首版技术方案

日期：2026-10-28。

## 已确定

- **前端：** 微信原生小程序，JavaScript、WXML、WXSS、JSON。
- **原因：** 当前 MVP 以原生页面与云接口为主，采用 JS 减少类型声明和编译配置，前后端可以共用同一语言。复杂字段和状态在实现时配合必要的 JSDoc 与服务端校验维护。
- **后端：** 按用户说明采用微信云开发文档型云数据库与 JavaScript 云函数，不直连 MongoDB。EnvID `cloud1-d0gyv1btk3ea9e858` 已配置；环境关联、实际模式及真实调用尚未由本项目验证。
- **管理界面：** 同一小程序的独立管理分包，`identity` 云函数查询 `admin_bindings` 决定访问权限；内容维护业务后续接入。
- **外部依赖：** 当前前端使用原生 API，不引入 UI 框架和运行时 npm 包，不需要 TypeScript 构建。
- **资源：** 使用已确认的 V3 双羊头像；底部导航采用原生 tabBar 与自有 SVG 导出的 PNG。

## 本阶段范围

0.2.0 已新增身份云函数、用户身份建立/恢复、内部用户 ID 展示、三击管理员核验和管理分包。尚未在云端部署或初始化绑定；目标环境可用性不由本地替身测试推定。活动与打卡仍明确展示“准备中”，不生成虚构记录。

## 下一阶段

1. 按 `docs/身份服务部署指引.md` 创建集合、设置客户端不可读写规则，部署 identity 并真实联调。

3. 验证唯一索引、事务和请求幂等后，接入个人清单与完成记录。
4. 依 PRD 分阶段补齐投稿、反馈、数据注销、指标和真机验收。

方案不改变 PRD 对日期、状态和权限的要求。JavaScript 的字段校验、数据库约束与服务端权限不能由前端类型声明或按钮状态替代。
