# 身份服务部署与管理员初始化

当前版本：0.2.0。技术路线：微信云开发文档型云数据库 + JavaScript 云函数。目标环境：`cloud1-d0gyv1btk3ea9e858`，小程序：`wxb7e6889ef5fe7e88`。

本地已完成代码和替身测试，尚未连接目标环境创建资源或部署。以下操作由有该环境管理权限的账号在微信开发者工具与云开发控制台完成。

## 1. 创建集合并限制客户端访问

在目标环境的数据库中新建两个空集合：

| 集合 | 用途 | 唯一约束 |
| --- | --- | --- |
| `users` | 微信身份关联与账号状态 | 系统 `_id` 唯一，云端根据真实调用上下文计算 |
| `admin_bindings` | 受控管理员绑定 | `_id` 与该绑定的 `user_id` 相同，保证每用户只有一条绑定 |

将两个集合的客户端权限设置为所有客户端均不可读写，使用自定义规则时等价为：

```json
{
  "read": false,
  "write": false
}
```

通过受信任的云函数服务端 SDK 访问集合，不给小程序客户端直接读写用户和管理员表的权限。此规则不代表其他业务集合已设计完成，后续分别配置。

用户记录由首次主动建立身份时创建；仅打开“我的”时查询既有身份，不创建账号。不要手工填写 OpenID 或允许客户端传入当前用户 ID 作为身份来源。

## 2. 部署 identity 云函数

1. 在微信开发者工具导入仓库根目录，确认当前 AppID 和云环境正确。
2. 为 `cloudfunctions/` 选择上述云环境；选中 `cloudfunctions/identity`，执行“上传并部署：云端安装依赖”（名称随工具版本可能略有不同）。
3. 等待 `wx-server-sdk@3.0.1` 依赖安装及函数部署完成。SDK 发布版本已通过包注册表核对，不需要在前端构建 npm。
4. 编译小程序，在“我的”点击“建立微信身份”，阅读用途说明并确认。
5. 成功后“我的”显示内部用户 ID；再次打开页面通过云端恢复身份。函数只向客户端返回内部 ID、默认展示名和业务日期，不返回 OpenID。

云函数使用 `cloud.DYNAMIC_CURRENT_ENV`，实际数据库取决于函数部署环境；因此前端 EnvID 与部署位置必须一致。不要把云函数本地调试缺少 OPENID 的结果当成真实微信身份；由小程序实际调用验证。

本函数没有 HTTP 入口，不接受请求中的 OpenID、AppID、用户 ID 或角色决定身份。账号状态不是 active、AppID 不匹配、数据库异常时均停止授权。

## 3. 初始化首位管理员

账号持有人先完成正常身份建立，在“我的”复制**内部用户 ID**，例如 `u_…`。该 ID 不等于微信号、AppID 或 OpenID。

由环境负责人核实账号归属，在云控制台的 `admin_bindings` 集合创建一条记录；以下两处占位都替换为复制的完整内部用户 ID：

```json
{
  "_id": "替换为完整内部用户ID",
  "user_id": "替换为同一个完整内部用户ID",
  "role": "admin",
  "status": "enabled"
}
```

记录本次操作人、时间、账号归属与变更原因，保留在受控运维记录中。小程序不提供自助开通或修改管理员身份的入口；任何新增、恢复与停用均按同样流程核实并留存变更记录。后续管理员运维工具接入时实现统一操作审计，不将手工初始化冒充已实现的后台账号管理功能。

绑定完成后：我的 → 关于 → **3 秒内点击版本号 3 次**。服务端核验通过后进入管理分包；页面每次显示都重新核验。停用时将对应绑定的 status 改为 disabled，后续请求不再通过；前台已经显示的信息在下次核验时清除。

当前工作台只有经过核验后显示的开发状态，**活动录入、发布、统计和其他运营模块尚未实现**，不会展示模拟管理数据。新增管理接口时必须在对应接口独立重复权限校验，不能只依赖本次入口核验。

## 4. 体验验证

- 普通账号建立身份后，没有绑定时三击应提示“当前账号没有管理权限”。
- 有效绑定的账号三击后进入工作台；移到后台再回来会重新核验。
- 停用管理员绑定后再次进入工作台应失败，旧页面不能因之前缓存过成功而重新授权。
- 切换页面过程中较早请求的延迟结果，不应导致隐藏页面跳转或覆盖新核验结果。
- 不要将缺少集合、函数未部署或网络失败误报成无管理权限；页面会显示相应服务异常说明。

## 5. 当前限制

目前采用内存中的公开用户资料加云开发的微信调用上下文，没有额外自定义 bearer token，也不把角色写入本地永久缓存。角色读取发生在每次服务端核验中。

本阶段不实现账号注销服务、删除后重新注册、服务端会话撤销或完整运营审计系统。界面也不开放这些操作。后续接入注销时须同时停用/清理绑定及身份关联，按 PRD 实现新账号与数据清理语义，不能仅删除用户文档而遗留管理员绑定。

数据库协议兼容性不影响此实现：我们使用 CloudBase 文档型数据库 SDK，不直连 MongoDB，也不把任意 MongoDB 事务或查询特性视为天然可用。并发首次登录使用确定性 `_id` 唯一约束，SDK 实际行为仍需真实云端验证。
