# 身份服务部署与管理员初始化

当前版本：0.5.0。技术路线：微信云开发文档型云数据库 + JavaScript 云函数。目标环境：`cloud1-d0gyv1btk3ea9e858`，小程序：`wxb7e6889ef5fe7e88`。

账号持有人已确认 0.4.0 验证通过。0.5.0 新增个人清单与手动完成接口，本地代码和替身测试不等于云端已更新。**已运行 0.4.0 的环境只需核对/补齐本节索引、更新 catalog 云函数并编译前端，identity 无需重复部署，存储规则无需变更**。保留既有集合和数据，不要删除重建；全新环境仍按全文初始化。

## 1. 创建集合并限制客户端访问

在目标环境中保留既有集合，并补齐以下集合：

| 集合 | 用途 | 唯一约束 |
| --- | --- | --- |
| `users` | 微信身份关联与账号状态 | 系统 `_id` 唯一，云端根据真实调用上下文计算 |
| `admin_bindings` | 受控管理员绑定 | `_id` 可由数据库自动生成；按 `user_id` 关联用户，为 `user_id` 创建唯一索引，保证每用户只有一条绑定 |
| `user_activities` | 当前用户加入的活动关系 | 唯一索引 `user_id + activity_id`；统计时筛选 `status=active` |
| `activity_views` | 用户活动详情浏览记录 | 唯一索引 `user_id + activity_id`；统计按 `activity_id` 去重 |
| `checkins` | 用户手动完成记录 | 唯一索引 `user_id + activity_id + period_key`；完成活动数按 `activity_id` 去重 |
| `platforms` | 活动所属平台 | 系统 `_id` 唯一 |
| `activities` | 运营维护的活动目录与核验状态 | 系统 `_id` 唯一 |
| `catalog_images` | 步骤图片登记与短期上传凭证 | 正式图片 `_id` 为云文件 ID 的 SHA-256；暂存凭证以 `upload_` 开头，客户端禁止直接读写 |
| `catalog_snapshots` | 用户目录分页候选快照，15 分钟过期 | 系统 `_id` 唯一 |
| `catalog_requests` | 管理及个人写操作幂等结果 | 系统 `_id` 唯一；管理结果以 `r_`、个人结果以 `ur_` 开头，与用户及请求 ID 绑定 |
| `audit_logs` | 平台、活动管理操作审计 | 系统 `_id` 唯一；每次管理变更一条 |

将以上所有集合的客户端权限设置为所有客户端均不可读写，使用自定义规则时等价为：

```json
{
  "read": false,
  "write": false
}
```

通过受信任的云函数服务端 SDK 访问集合，不给小程序客户端直接读写用户、管理员或目录数据的权限。

启动小程序即调用 `identity.login` 建立或恢复账号，三个 tab 在显示时重新核验，失败可重试。不要手工填写 OpenID 或允许客户端传入当前用户 ID 作为身份来源。资料编辑为可选操作，登录本身不采集头像昵称。

`user_activities` 与 `checkins` 由用户通过小程序真实加入/完成后写入，不要手工添加模拟记录，也不要清空已有数据。目录上线前由运营录入并核验真实平台与活动；用户进入详情时 `catalog` 写入 `activity_views`。

除表中唯一索引外，按云控制台提示建立以下索引（未标注的均为升序）；组合字段中的 `_id` 用于与函数排序一致，已有相同索引不重复创建：

| 集合 | 索引字段及方向 | 用途 |
| --- | --- | --- |
| `user_activities` | `user_id + status` | 个人清单统计 |
| `user_activities` | `user_id + _id` | 0.5.0 个人关系稳定扫描 |
| `checkins` | `user_id + checkin_date + _id` | 0.5.0 当天完成事实 |
| `checkins` | `user_id + period_key + _id` | 0.5.0 已完成的一次性活动 |
| `checkins` | `user_id 升序 + completed_at 降序 + _id 降序` | 0.5.0 完成历史倒序分页 |
| `platforms` | `status + _id` | 公开目录核验启用平台并稳定扫描 |
| `activities` | `publication_status + verification_status + content_restricted + _id` | 公开活动候选查询 |
| `activities` | `publication_status + _id` | 运营状态筛选与分页 |
| `activities` | `platform_id + publication_status` | 停用平台前统计已发布活动 |

业务集合中的 `user_id`、`activity_id`、`period_key` 使用字符串，避免混合类型。若控制台提示所需索引缺失，应按错误提示补建后再验证，不要通过开放客户端权限规避。

`completed_at`、加入/移除时间和幂等结果 `created_at` 由云函数写入数据库 Date 类型，不要手工改成字符串。`user_activities` 的 `user_id + activity_id` 与 `checkins` 的 `user_id + activity_id + period_key` 必须配置唯一索引；若遇到重复旧数据，先核实归属及保留策略，不能直接删除用户完成记录。

当前不自动清理 `catalog_requests`，**不要为该集合设置 TTL 或手动删除新个人请求结果**；否则跨日响应丢失时无法恢复原请求语义。后续清理需另行设计可证明安全的保留/过期协议。`catalog_snapshots` 的分页过期与个人请求幂等是两种不同机制。

### 验证事务支持

`catalog` 的管理变更、审计、幂等请求记录、浏览去重及个人清单/完成写入使用数据库事务。部署前在目标环境用云函数实际调用 SDK 验证 `db.runTransaction`、事务内文档读取/写入和提交行为。0.5.0 新个人事务对用户及相关关系/活动/平台写入内部 `_checkin_guard`，用于使并发停用/暂停/移除产生写冲突后重新核验；该字段不改变运营修订号或更新时间，不能在维护工具中主动删除/重置。验证冲突与重试，检查失败无半条关系、完成或请求结果；同平台写争用也需验证延迟。事务失败不降级为多条独立写操作。

## 2. 部署 identity 云函数

1. 在微信开发者工具导入仓库根目录，确认当前 AppID 和云环境正确。
2. 为 `cloudfunctions/` 选择上述云环境；选中 `cloudfunctions/identity`，执行“上传并部署：云端安装依赖”（名称随工具版本可能略有不同）。
3. 等待 `wx-server-sdk@3.0.1` 依赖安装及函数部署完成。SDK 发布版本已通过包注册表核对，不需要在前端构建 npm。
4. 重新编译小程序，启动即自动登录；“发现活动”登录中显示遮罩，成功后解锁，失败提供微信登录重试按钮。
5. “我的”展示当前账号资料及三项云端统计。内部用户 ID 位于页面底部，点击可复制完整 ID。函数不向客户端返回 OpenID。
6. 头像昵称不能静默取得。点“编辑资料”主动选择头像、填写昵称并保存。新用户不填写也可登录，仍显示默认头像和“微信用户”。

头像由 `identity.saveProfile` 在服务端上传，云路径为 `user-avatars/<内部用户ID>/<随机文件名>`。保持云存储默认权限或收紧为仅管理端访问，不需要给客户端开放写入权限；函数使用服务端 SDK 上传、删除旧头像，并生成临时访问链接。不要为此开放数据库客户端写权限。头像格式为 JPG/PNG/WebP，大小不超过 1MB；昵称 1–24 字。

若只保存昵称正常而选择头像失败，检查当前环境云存储与云函数执行角色的上传、删除和临时链接权限，查看云函数错误码；不要通过给全体用户开放读写来修复。上线前同步小程序平台的隐私保护指引与实际资料用途，并在真机检查头像选择、昵称填写和保存结果。

云函数使用 `cloud.DYNAMIC_CURRENT_ENV`，实际数据库取决于函数部署环境；因此前端 EnvID 与部署位置必须一致。不要把云函数本地调试缺少 OPENID 的结果当成真实微信身份；由小程序实际调用验证。

本函数没有 HTTP 入口，不接受请求中的 OpenID、AppID、用户 ID 或角色决定身份。账号状态不是 active、AppID 不匹配、数据库异常时均停止授权。

## 3. 初始化首位管理员

账号持有人先完成自动登录，在“我的”底部点击用户 ID 行，复制**完整内部用户 ID**，例如 `u_…`。屏幕上仅缩略展示，复制值为完整值。该 ID 不等于微信号、AppID 或 OpenID。

由环境负责人核实账号归属，在云控制台的 `admin_bindings` 集合创建一条记录；只需将 `user_id` 替换为复制的完整内部用户 ID，`_id` 由数据库自动生成，无需手工填写或修改：

```json
{
  "user_id": "替换为完整内部用户ID",
  "role": "admin",
  "status": "enabled"
}
```

如果控制台使用逐字段编辑，新增 `user_id`、`role`、`status` 三个字符串字段，分别填写内部用户 ID、`admin`、`enabled`，保留自动生成的 `_id`。

本次调整将管理员查询从按 `_id` 查找改为按 `user_id` 查找。**使用本指引前，需重新上传并部署更新后的 `identity` 云函数（云端安装依赖）**，仅修改数据库记录不能修复旧版函数的查询方式。之前已按旧指引创建、且 `user_id` 正确的单条绑定仍兼容，无需重建。

按 PRD 对用户绑定唯一性的要求，在 `admin_bindings` 的索引管理中为 `user_id` 创建升序唯一索引。已有重复数据须先核实并清理，否则唯一索引无法建立。每位用户只保留一条绑定，停用或恢复时修改原记录的 `status`，不要追加另一条绑定。函数也会检查重复记录，发现同一 `user_id` 有多条记录即拒绝授权，不会从中任意选取一条。

记录本次操作人、时间、账号归属与变更原因，保留在受控运维记录中。小程序不提供自助开通或修改管理员身份的入口；任何新增、恢复与停用均按同样流程核实并留存变更记录。后续管理员运维工具接入时实现统一操作审计，不将手工初始化冒充已实现的后台账号管理功能。

绑定完成后：我的 → 关于 → **3 秒内点击版本号 3 次**。服务端核验通过后进入管理分包；页面每次显示都重新核验。停用时将对应绑定的 status 改为 disabled，后续请求不再通过；前台已经显示的信息在下次核验时清除。

当前工作台已包含平台管理、活动草稿、内容复核、发布/暂停/结束与管理操作审计。活动内容只能使用真实来源和核验结果；不要录入模拟活动供公开展示。每个管理接口都独立校验当前账号和管理员绑定，入口核验不能代替服务端权限判断。

## 4. 部署 catalog 与 0.5.0 前端

1. 按第 1 节补建目录集合、权限和索引；按事务检查步骤确认环境能力。
2. 选中 `cloudfunctions/catalog`，选择同一云环境，执行“上传并部署：云端安装依赖”。目录已锁定 `wx-server-sdk@3.0.1`。
3. 确认部署列表中 `identity` 与 `catalog` 都在目标 EnvID；`catalog` 通过微信云调用上下文识别账号，不接受客户端传入用户 ID 或 OpenID。
4. 在开发者工具重新编译 0.5.0 前端；普通用户进入活动广场验证登录、搜索、分类、两个快捷筛选、分页、活动详情和返回后的个人浏览数，并按下节验收加入/完成/记录闭环。
5. 管理员通过“我的 → 关于 → 3 秒内点击版本号 3 次”进入工作台。先新增平台，再录入活动草稿；保存后填写实际核验说明并记录核验，通过后再发布。
6. 验证发布活动出现在广场；编辑已发布活动后应变成待核验并暂时离开广场。暂停、平台停用或核验过期都应即时停止展示可执行入口；停用平台前确认影响数。

### 4.1 0.5.0 升级与验收

0.4.0 已验证的环境无需重新初始化管理员、重新录入活动或更改存储规则。检查 `user_activities`、`checkins` 已存在，补齐第 1 节唯一和查询索引，然后上传部署 `catalog`（云端安装依赖）、重新编译前端。identity 既有统计接口直接使用新记录；不要用清空数据库排查问题。

| 验收场景 | 预期 |
| --- | --- |
| 广场/详情加入同一活动，多次点击或重试 | 只有一条关系；“我的”打卡活动数增加一次 |
| 今日待完成 → 参与第三方 → 返回 | 重新读取状态；不会自动完成，须主动点“标记完成” |
| 完成弹窗 | 显示服务端北京时间日期和手动确认说明；取消不写，首版不可撤销/补卡 |
| 每日任务重复确认 | 同周期只有一条记录，进度更新；跨日满足条件后重新待办 |
| 旧页面跨日首次确认 | DATE_CHANGED；刷新后再次明确确认，不能自动写到新一天 |
| 完成成功但客户端响应丢失，跨日/重启重试 | 复用原请求 ID 和原日期，返回原记录；不静默创建新一天的记录 |
| 一次性完成 → 次日 → 移除 → 重加 | 原记录保留，仍在“一次性已完成”，不回今日待办 |
| 全部页移除与重新加入 | 移除需确认；首次加入时间、历史记录保留；重加恢复原关系 |
| 完成后暂停/结束/移除 | 仍在今日“已完成”及当天进度，历史保留；新确认按当前状态限制 |
| 确认与暂停/平台停用/移除并发 | 已先成功的结果可重放；冲突后重新核验，不基于旧快照新增记录 |
| 今日/全部与五项全部筛选 | 每日今日已完成仍属进行中；不可执行项显示具体原因；空任务不显示 0/0 |
| 我的 → 打卡记录 | 时间倒序，每页 20；同时间用 ID 稳定分页；标题/平台为完成快照 |
| 受限内容、不同账号、伪造 user_id | 受限标题/平台不展示；只读取/写入当前微信账号数据 |
| 返回“我的”看统计 | active 关系数、去重浏览活动数、去重完成活动数真实变化；同活动跨日完成只计一个完成活动 |
| 网络失败/事务失败/读取失败 | 结果未知明确提示待确认并保留请求；不填假进度、不留下部分提交，可重试 |

使用现有已核验的每日和一次性活动测试。跨日场景应使用隔离环境及可控服务端时间测试，不能只修改手机时间，也不能改生产历史记录。自动化替身测试不替代目标 CloudBase 事务、索引、iPhone/Android 页面和真实外部小程序往返验收。

### 精简活动采集与图文步骤（2026-10-29 更新）

本次修改必须重新部署 `catalog` 云函数、补建 `catalog_images` 集合并重新编译前端。无需删除旧活动；旧的文字步骤、奖励/门槛/注意事项和 AppID/路径入口均保留读取兼容。旧记录首次编辑时合并展示为“活动信息”，保存修改后须重新核验。

- 基本信息仅填写所属平台、名称、奖励类型、频率、目录搜索关键词和活动信息。活动信息最多 3000 字，合并奖励、资格与注意事项；列表摘要取第一行，最长 120 字。
- 参与方式填写入口类型、目标地址、参与搜索词和逐条图文步骤。网页目标地址使用 HTTPS；小程序使用微信右上角菜单“复制链接”所得的完整 `#小程序://名称/链接`，无需另外提供 AppID 与路径。平台搜索与人工步骤不显示目标地址。
- 每个活动最多 20 步、总计 2000 字，每步最多 3 张图、活动最多 9 张；原图不设业务文件大小上限，选择后自动压缩为受支持图片再上传，不要求用户预先压缩。正式图片使用 `activity-steps/<用户ID>/` 云存储路径，不开放客户端直接写权限。详情与管理读取时返回临时链接，链接失败显示图片暂不可用，不丢弃文字。
- 管理分包使用 Vant Weapp 1.11.7 Uploader，选图时请求微信压缩，合规原生压缩结果直接使用；仍是 HEIC 或体积过大时回退 Canvas JPEG，最长边从 2560 像素起先降质量再降尺寸，目标 900KB。客户端只读取成品文件头，不整文件读入 Base64。云端 1MB 校验保护压缩成品，原图不设业务文件大小上限。失败图片保留缩略图可点击重试，或删除后继续；上传中不允许修改步骤和保存。
- 图片上传失败不会统一提示“云函数未部署”；仅明确函数不存在时提示部署，其余显示网络、超时、请求大小或调用错误码。开发者工具控制台保留 `catalog:call_failed` 的 action、错误码和截断的原始错误消息，不打印图片 Base64；定位真实云端问题时对照同环境的云函数日志。
- 图片登记和文件上传不属于数据库管理变更事务；登记失败会尝试删除刚上传的文件。移除步骤图片仅移除引用，取消或未保存的上传可能留存文件；清理时须核对所有活动的图片引用和文件登记，不能直接批量删除目录。
- 期限与来源仅保留期限类型、开始和结束日期。非固定期限自动清空并禁用结束日期，日期按北京时间全天保存；清除控件仅在已选日期时展示。来源核查由“本次核验说明”记录，维护责任人和核验期限由服务端生成。
- 管理员实际验证目标小程序后，在核验区勾选“已在微信真机验证小程序跳转”并记录核验。未勾选仍可核验发布，但只提供复制入口及步骤；勾选后开启“打开活动小程序”。编辑内容会关闭直达并要求重新核验。
- 使用 [`wx.navigateToMiniProgram.shortLink`](https://developers.weixin.qq.com/miniprogram/dev/api/navigate/wx.navigateToMiniProgram.html)（基础库 2.18.1 起），由用户点击触发并经过微信确认。打开前重新读取可执行状态；取消、失败或不支持时保留复制和图文步骤。开发者工具不会真的跳转，须在 iOS/Android 微信真机验证给定链接，不把 API 调用成功当作参与完成。

### Vant Uploader 与图片文件直传（2026-10-29 更新）

本次改用 **`wx.cloud.uploadFile` 云存储原生接口**，不需要购买服务器或域名，也不需要配置 `uploadFile` 合法域名。必须重新上传并部署 `catalog`（云端安装依赖）、设置下面的云存储安全规则，再重新编译前端；无需新增数据库集合。服务端仅直接依赖 `wx-server-sdk@3.0.1`，不再调用预签名接口。在云控制台检查 catalog 函数配置，执行超时建议设为 **60 秒**，以容纳冷启动、存储下载校验和正式文件写入。

1. 确认 `catalog_images` 集合已存在且客户端读写均禁止；该集合同时记录短期凭证和正式文件。
2. 进入微信开发者工具的“云开发 → 云存储 → 权限设置”，确认环境为 `cloud1-d0gyv1btk3ea9e858`，选择“自定义安全规则”，应用下方 JSON。规则文件同时保存在 `cloudfunctions/catalog/storage.rules.json`，它不会随云函数部署自动生效，需在控制台保存。
3. 规则只允许当前用户写入自己创建的 `activity-step-staging/` 暂存文件，禁止客户端读取文件及写入正式目录；服务端 SDK 不受客户端规则限制。`catalog_images` 和其他数据库集合仍保持客户端禁读写。如果环境还有其他业务的定制规则，按前缀合并这项暂存授权，不能直接覆盖其他业务的规则。
4. 安全规则按官方说明通常需要 1–3 分钟生效；等待生效后重新编译并生成新的预览二维码。无需修改公众平台服务器域名，也无需关闭“合法域名校验”。
5. iPhone 微信相册分别测试原 HEIC、普通照片、截图、大图和多图；核对压缩、上传、云端校验、缩略图、预览、失败重试/删除及保存后重新进入。开发者工具依赖宿主机文件选择与解码能力，即使使用 Vant 也不能保证能选择 HEIC，真实兼容性以微信真机为准。

在本项目独占的云存储环境中，使用以下规则：

```json
{
  "read": false,
  "write": "auth != null && resource.openid == auth.openid && /^activity-step-staging\\//.test(resource.path)"
}
```

规则含义：只有当前微信用户可写自己创建的暂存文件，`activity-steps/` 正式图片和 `user-avatars/` 头像仍只能由云函数写入；预览继续使用服务端生成的临时链接。普通账号即使自行调用 SDK 上传暂存文件，也不能调用管理员接口申请、完成或登记正式步骤图片。参考 [CloudBase 云存储安全规则](https://docs.cloudbase.net/storage/security-rules)。

新流程为：`prepareStepImageUpload` 核验管理员并分配随机暂存路径 → `wx.cloud.uploadFile` 在指定环境发送文件 → `completeStepImageUpload` 校验返回的云文件 ID 属于当前云环境及本次暂存路径，事务绑定该文件后下载、核对格式/体积、另存正式路径并事务登记。凭证业务有效期 10 分钟，仅当前有效管理员可完成；重复完成返回同一正式图片，取消只清理该暂存路径的文件。暂存路径为 `activity-step-staging/`，正式路径仍为 `activity-steps/`；客户端不能覆盖已登记的正式图片。旧 Base64 接口保留兼容；上一版普通 wx.uploadFile 前端需重新编译更新，不再返回预签名字段。

成功或取消后尽力清理暂存文件；断网、进程退出或客户端再次写入可能留存暂存对象。可在存储控制台为**仅 `activity-step-staging/` 前缀**配置至少 1 天的生命周期清理，不能作用于正式目录。未设置自动清理时需人工维护，不能将全部图片登记按过期凭证删除。

报错按阶段定位：`图片上传凭证申请` 失败查看 catalog 对应 action 日志；`图片云存储上传` 失败查看 `step-image:storage_failed` 的错误码（权限、网络、超时），权限错误先检查上述存储规则；`图片云端校验` 失败查看 `completeStepImageUpload` 日志（存储读取、真实格式、集合、事务和超时）。`-1` 只是通用错误码，不能仅凭它断言是 HEIC 或云函数未部署。新版不会再打印 `step-image:upload_host`；若仍见“uploadFile 合法域名”错误，请重新编译并生成新二维码，确认没有运行旧版前端。不要打印、转发完整上传凭证或图片 Base64。

Vant 官方组件所需编译产物已经随项目放在管理分包，无需开发者工具“构建 npm”。维护依赖时，在仓库根目录运行 `npm ci`、`npm run build:vendor`，从锁定的官方包重新生成 34 个所需依赖文件并保留 MIT 许可证。参考：[Vant Weapp Uploader](https://vant-ui.github.io/vant-weapp/#/uploader)。

`catalog_snapshots` 是 15 分钟分页快照；用户刷新或更改条件后会建立新快照。`activity_views` 按用户与活动去重，首次进入详情后统计可能有短暂云端延迟。目录列表、内容维护和浏览记录均从云函数访问，所有集合禁止客户端直接读写。

## 6. 当前限制

目前采用内存中的当前用户展示资料加云开发的微信调用上下文，没有额外自定义 bearer token，也不把角色写入本地永久缓存。角色读取发生在每次服务端核验中；三个 tab 显示时调用登录接口重新核实账号状态。

本阶段不实现账号注销服务、删除后重新注册、服务端会话撤销或完整运营审计系统。界面也不开放这些操作。后续接入注销时须同时停用/清理绑定及身份关联，按 PRD 实现新账号与数据清理语义，不能仅删除用户文档而遗留管理员绑定。

数据库协议兼容性不影响此实现：我们使用 CloudBase 文档型数据库 SDK，不直连 MongoDB，也不把任意 MongoDB 事务或查询特性视为天然可用。并发首次登录使用确定性 `_id` 唯一约束，SDK 实际行为仍需真实云端验证。

0.5.0 已包含加入个人打卡清单、移除重加、手动完成及历史；尚不包含投稿、活动级问题反馈处理、账号注销、提醒、撤销或补卡。小程序短链只有管理员明确登记真机核验后才启用按钮，网页入口仍使用主动复制。`npm test` 和本地替身测试只验证业务规则，不代替 CloudBase 事务、索引、WXML/WXSS 编译与微信真机联调。
